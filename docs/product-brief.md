# 제품 브리프와 MVP 판정 기준

이 문서는 MVP 범위, 성공 기준, 구현 상태, 릴리즈 게이트의 기준 문서다. README와 Notion 전달 문서는 이 문서를 요약하며, 상태가 달라지면 이 문서와 요약 문서를 같은 변경에서 함께 갱신한다.

## 한 줄 정의

잘살아보세는 함께 사는 사람들이 공동 지출, 냉장고 재고처럼 반복적으로 관리해야 하는 생활 요소를 한 곳에서 공유하고 운영할 수 있도록 돕는 공동생활 관리 앱이다.

## 초기 타겟

PRD의 보완 의견을 반영해 1차 MVP는 신혼부부 또는 동거 커플처럼 함께 살기 시작한 2인 가구에 초점을 둔다.

## MVP 핵심

- 가구 만들기와 초대하기
- 홈에서 오늘 할 일 보기
- 캘린더에서 날짜별 생활 이벤트 보기
- 월 공동생활비와 구성원 부담금 설정
- 지출 등록, 납부 상태, 잔액과 정산 안내 관리
- 냉장고 항목 등록과 유통기한 알림

## 상태 판정 방식

- `구현 완료`: 제품 코드와 저장 경로가 연결되어 있다.
- `자동 검증`: 저장소의 단위·규칙·스모크 테스트로 동작을 반복 확인할 수 있다.
- `수동 검증 필요`: 운영 Firebase나 실제 iOS/Android 기기에서 확인해야 한다.
- `범위 제외`: 이번 MVP에서 노출하거나 새로 저장하지 않는다.

구현 완료는 릴리즈 완료를 뜻하지 않는다. 아래 성공 기준을 모두 충족하고 릴리즈 게이트의 증거를 남겨야 외부 릴리즈 가능으로 판정한다.

## 측정 가능한 성공 기준

| ID | 사용자 결과 | 통과 조건 | 현재 상태 |
| --- | --- | --- | --- |
| SC-01 | 두 사람이 한 가구를 안전하게 공유한다 | 서로 다른 테스트 계정 2개 중 첫 계정이 가구를 만들고 두 번째 계정이 초대 코드로 참여한다. 두 계정 모두 같은 지출·냉장고 데이터를 읽고 쓸 수 있고, 제3 계정의 읽기·쓰기는 거부된다. | 구현 완료, Emulator/스모크 검증 경로 있음 |
| SC-02 | 공동 지출과 냉장고 재고를 끝까지 관리한다 | 지출과 냉장고 항목을 각각 1개 이상 생성·수정·상태 변경·삭제하고, 저장 결과가 구독 중인 화면에 반영된다. | 구현 완료, Firebase CRUD 스모크 경로 있음 |
| SC-03 | 월 생활비와 두 사람의 부담금이 정확하다 | 2인 가구에서 월 예산 1건을 저장했을 때 두 부담금의 합이 예산과 일치하고, 선택 월 지출을 뺀 잔액과 누적 지출 기준 정산 금액이 테스트 기대값과 일치한다. 동시 수정 2건 중 오래된 1건은 충돌로 거부된다. | 구현 완료, 단위·Emulator 테스트 있음 |
| SC-04 | 날짜 기반 정보를 한눈에 찾는다 | 납부일이 있는 지출 1건과 유통기한이 있는 냉장고 항목 1건이 해당 날짜의 캘린더에 표시되고, 오늘 또는 임박 조건을 만족하면 홈 요약에도 표시된다. | 구현 완료, 화면 수동 검증 필요 |
| SC-05 | 기기 알림을 통제할 수 있다 | iOS와 Android 실제 기기에서 미래 알림 대상 1건 이상을 예약해 OS 예약 목록과 앱 표시 개수가 일치하고, 취소 후 앱이 만든 예약이 0건임을 확인한다. 권한 거부 시 오류 대신 안내를 표시한다. | 예약·취소 구현 완료, 실제 기기 검증 필요 |
| SC-06 | 지원 화면에서 치명적 회귀가 없다 | 320px, 375px, 402px 너비에서 로그인, 가구 설정, 홈, 캘린더, 지출, 냉장고의 주요 액션을 완료하며 P0/P1 결함, 화면 겹침, 잘린 필수 액션이 각각 0건이다. | 디자인 QA 증거 있음, 릴리즈 후보 재검증 필요 |

| 로그인·가구 | Firebase 이메일 로그인/회원가입, 가구 생성, 초대 코드 참여, 최대 2인 가구 격리 구현 완료 | Firestore Rules 정적·Emulator 테스트와 2계정 스모크 경로 제공 | 릴리즈 Firebase 프로젝트에서 2계정 스모크 재실행 |
| 홈·캘린더 | 지출 납부일, 냉장고 유통기한, 월간 요약의 실시간 데이터 연결 완료 | 데이터 연결 회귀 테스트와 기존 디자인 QA 증거 있음 | 릴리즈 후보 브라우저·기기 흐름 재확인 |
| 지출·생활비 | 지출 CRUD/납부 상태, 월 공동생활비, 50:50 또는 직접 부담금, 잔액, 누적 정산 안내 구현 완료 | 월 예산·정산 단위 테스트와 Rules 테스트 있음 | 실제 2계정 동시 수정 확인 |
| 냉장고 | CRUD, 소진/폐기, 선택 유통기한과 항목별 알림 여부 구현 완료 | Firebase CRUD 스모크 경로 있음 | 실제 기기 입력과 상태 변경 확인 |
| 알림 | 정책 계산, 대상 수 표시, Expo 로컬 예약·취소 구현 완료 | 웹의 미지원 분기 확인 가능 | iOS/Android 권한·예약·취소 수동 검증 |
| 디자인 | 공통 테마와 320~402px 반응형 화면 적용 완료 | `design-qa.md`와 캡처 자산에 검증 기록 있음 | 릴리즈 후보에서 접근성·회귀 재검증 |
| 집안일 | 활성 탭·데이터 경로·알림에서 제외 | 안전 제거 회귀 테스트 있음 | 보존 데이터 정책만 유지 |
| 외부 배포 | 앱 실행·정적 웹 export 경로 제공 | 로컬/CI 검증 명령 제공 | 배포 환경, 실제 기기, 아이콘·splash, 스토어 메타데이터 필요 |

따라서 현재 상태는 `기능 구현 완료, 외부 릴리즈 준비 중`이다. 실제 기기와 릴리즈 Firebase 검증을 끝내기 전에는 외부 릴리즈 완료로 표시하지 않는다.

## 릴리즈 게이트

아래 항목은 모두 필수이며, 실행 날짜·대상 커밋·결과를 릴리즈 기록에 남긴다.

| ID | 통과 조건 | 증거 |
| --- | --- | --- |
| RG-01 | 릴리즈 후보 커밋에서 `npm run qa:test`, `npm run verify`, `npm run test:firestore-rules`가 모두 종료 코드 0으로 끝난다. | CI 링크 또는 명령 로그 |
| RG-02 | Mock이 아닌 릴리즈 Firebase에서 서로 다른 2계정으로 `npm run smoke:firebase`를 실행하고 초대·가구 격리·양쪽 계정 CRUD가 건너뜀 없이 통과한다. | 비밀값을 제거한 스모크 결과와 실행 시각 |
| RG-03 | 지원할 iOS와 Android 기기에서 `docs/device-testing.md`의 핵심 흐름과 SC-05 알림 예약·취소를 각각 1회 통과한다. | 기기/OS 버전, 체크리스트 결과 |
| RG-04 | `EXPO_PUBLIC_USE_MOCKS=false`인 배포 환경과 Firestore Rules 배포를 확인하고 앱 아이콘, splash, 개인정보 처리 안내, 스토어 문구·이미지를 준비한다. 누락 항목은 0개여야 한다. | 환경 확인 결과와 스토어 제출 체크리스트 |
| RG-05 | 열린 P0/P1 결함이 0건이고 SC-01~SC-06이 모두 통과 상태다. | 이슈 필터와 성공 기준 체크 결과 |

`npm run verify`가 Firebase 자격 증명 없이 smoke test를 건너뛸 수 있으므로 RG-02는 RG-01과 별도로 확인한다. Emulator 테스트도 기본 `npm run qa:test`에서는 환경이 없으면 건너뛰므로 `npm run test:firestore-rules`를 별도 필수 게이트로 둔다.

## 이번 MVP에서 제외

- 원격 푸시 발송 서버와 사용자별 알림 설정 동기화
- 송금 실행 또는 정산 완료 상태 저장
- 집안일 관리
- 가구별 세부 권한 관리
- 이미지 첨부와 영수증 인식

## 제품 톤

- 감시보다 협력
- 정산보다 함께 관리
- 잔소리보다 리마인드
- 평가보다 균형
- 완벽한 관리보다 생활의 빈틈 보완
