# 실제 기기 테스트 가이드

웹 프리뷰는 UI와 데이터 흐름 확인용이다. 알림, 키보드, 날짜 입력, 네이티브 권한은 실제 기기에서 다시 확인한다.

## 사전 준비

- `.env.local`에 Firebase Web App 값이 입력되어 있어야 한다.
- Firebase Authentication의 Email/Password provider가 활성화되어 있어야 한다.
- Firestore Database와 security rules 배포가 완료되어 있어야 한다.
- 테스트 계정 2개를 준비한다.

환경 확인:

```bash
npm run verify:env
```

반복 테스트용 데모 데이터 준비:

```bash
SMOKE_TEST_EMAIL=<테스트 계정 이메일> \
SMOKE_TEST_PASSWORD=<테스트 계정 비밀번호> \
npm run demo:seed
```

## 실행

iOS 시뮬레이터:

```bash
npm run ios
```

Android 에뮬레이터:

```bash
npm run android
```

실제 휴대폰에서는 Expo 앱으로 개발 서버의 QR 코드를 스캔해 확인한다. 알림 동작이 Expo 앱 환경에서 제한되면 개발 빌드로 다시 확인한다.

## 핵심 시나리오

1. 앱 최초 실행 시 로그인 화면이 보인다.
2. 새 계정으로 회원가입한다.
3. 가구를 만든다.
4. 홈에 가구명, 멤버 수, 초대 코드가 보인다.
5. 다른 계정으로 로그인해 초대 코드로 참여한다.
6. 지출을 등록하고 홈, 캘린더, 지출 화면에 반영되는지 확인한다.
7. 집안일을 등록하고 완료 처리 후 수행 비율이 바뀌는지 확인한다.
8. 냉장고 항목을 등록하고 소진/폐기 처리 후 요약이 바뀌는지 확인한다.
9. 앱을 종료하고 다시 열어도 로그인과 데이터가 유지되는지 확인한다.
10. 다른 가구의 데이터가 섞이지 않는지 확인한다.

## 알림 확인

1. 지출, 집안일, 냉장고 항목 중 미래 날짜 항목을 준비한다.
2. 홈의 `알림 준비 상태`에서 대상 수가 표시되는지 확인한다.
3. `로컬 알림 예약`을 누른다.
4. 권한 요청이 표시되면 허용한다.
5. 예약 완료 메시지와 예약 개수를 확인한다.
6. `예약 취소`를 눌러 취소 메시지를 확인한다.

실제 알림 수신은 운영체제와 앱 실행 상태에 따라 달라질 수 있으므로, 디자인 전 단계에서는 권한 요청, 예약 성공, 취소 성공까지만 필수 통과 기준으로 둔다.

## 실패 시 확인할 것

- `npm run verify:env`가 통과하는지 확인한다.
- Firebase Console에서 테스트 계정이 생성되어 있는지 확인한다.
- Firestore rules가 최신인지 확인한다.
- `.firebaserc`의 default project와 `.env.local`의 `EXPO_PUBLIC_FIREBASE_PROJECT_ID`가 같은지 확인한다.
- 웹에서는 로컬 알림 예약이 지원되지 않는 것이 정상이다.
