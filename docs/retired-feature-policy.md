# MVP 제외 기능 안전 제거 정책

JAL-53에서 집안일 관리, 담당자 배정, 점수와 수행률을 MVP 범위에서 제외했다. 이 문서는 코드에 의도적으로 남긴 호환 지점과 운영 절차를 정의한다.

## 데이터 보존과 접근

- 기존 `households/{householdId}/chores/{recordId}` 문서는 이번 배포에서 삭제하거나 변환하지 않는다.
- 새 앱은 해당 컬렉션을 구독하거나 캐시에 적재하지 않으며 생성, 수정, 삭제 API를 제공하지 않는다.
- 새 보안 규칙은 해당 경로의 읽기와 쓰기를 모두 거부한다. 다른 가구 데이터에 대한 권한이 넓어지는 예외는 없다.
- 레코드는 프로덕션 규칙 배포일로부터 최소 90일간 보존하고, 그 이후에도 별도 데이터 삭제 티켓, 개인정보 검토, 백업 및 삭제 결과 감사가 완료되기 전에는 삭제하지 않는다.
- 향후 내보내기나 마이그레이션은 앱 권한이 아닌 승인된 관리자 작업으로만 수행하며, 이 릴리스에는 마이그레이션 또는 삭제 작업을 포함하지 않는다.

## 구버전, 딥링크와 캐시

- `/chores`는 새 기능 진입점이 아니라 홈으로 즉시 이동하는 호환 경로다. 하단 탭에서는 숨긴다.
- 정적 웹 worker는 기존 북마크가 404가 되지 않도록 `/chores` HTML 경로를 계속 전달한다.
- Firestore 구독에서 해당 컬렉션을 제거했으므로 SDK 로컬 캐시에 과거 문서가 있어도 새 앱 상태나 홈, 캘린더에 노출되지 않는다.
- 과거 버전이 예약한 `chore-` 식별자 로컬 알림은 새 네이티브 앱 시작 시 취소한다.
- 규칙 차단 후 남아 있는 구버전은 해당 리스너의 권한 오류를 기존 데이터 오류 화면으로 처리하며 권한 상승이나 데이터 변경은 허용되지 않는다.

## 배포 순서

1. 새 클라이언트와 웹 빌드를 배포해 UI, 구독, 쓰기, 알림 진입점을 먼저 제거한다.
2. `/chores` 딥링크가 홈으로 이동하고 지출, 냉장고, 캘린더가 정상 동작하는지 확인한다.
3. 모바일 최소 지원 버전과 90일 보존 시작일을 릴리스 기록에 남긴다.
4. 구버전 유예 기간이 끝나면 `firestore.rules`를 배포해 보존 레코드의 읽기와 쓰기를 차단한다.
5. Firebase smoke test로 활성 컬렉션 CRUD와 제외 컬렉션 접근 거부를 확인한다.

규칙을 클라이언트보다 먼저 배포하지 않는다. 먼저 배포하면 구버전 실시간 리스너가 오류 상태로 전환될 수 있다.

## 롤백

- 규칙 배포 전 클라이언트 롤백은 이전 빌드 재배포만으로 가능하며 기존 데이터는 그대로 남아 있다.
- 규칙 배포 후 이전 빌드로 롤백해야 하면, 먼저 직전의 가구원 범위 규칙을 복원하고 접근 범위를 확인한 다음 클라이언트를 롤백한다.
- 롤백 중에도 컬렉션 삭제나 광범위한 관리자 권한 부여는 하지 않는다.
- 원인 해결 후에는 새 클라이언트, 접근 차단 규칙 순서로 다시 배포한다.

## 승인된 잔여 참조

- `src/app/chores.tsx`, `src/components/app-tabs.tsx`, `sites/worker.js`: 숨김 딥링크 리다이렉트
- `src/services/notification-service.ts`: 과거 로컬 알림 정리용 식별자
- `firestore.rules`, `scripts/firebase-smoke-test.mjs`: 보존 데이터 접근 차단과 검증
- `scripts/firebase-repair-household.mjs`: 보존 레코드가 있는 가구를 삭제하지 않게 막는 안전 조건
- QA 회귀 테스트와 이 문서: 위 호환 지점이 기능으로 다시 확장되지 않는지 검증
