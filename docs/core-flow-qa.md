# 핵심 사용자 흐름 QA

## 자동 회귀 범위

`npm run qa:e2e`는 실제 인증정보나 운영 데이터를 사용하지 않는 격리된 E2E mock 세션과 Chrome을 실행한다.

- 회원가입, 가구 생성, 로그아웃, 두 번째 계정 가입, 초대 코드 참여, 기존 계정 재로그인
- 월 공동생활비 생성·수정과 지출 생성·수정·삭제
- 냉장고 항목 생성·수정·삭제
- 캘린더 일정 생성·삭제
- 320px, 402px 모바일 웹과 1440px 데스크톱 웹의 가로 넘침
- 브라우저 오프라인 전환 시 사용자 상태 안내
- 보이는 입력과 버튼의 접근 가능한 이름
- `npm run verify`에서 iOS·Android·웹 번들 생성

집안일은 MVP에서 제외되었으므로 CRUD 회귀 대상이 아니다. `/chores` 리다이렉트와 데이터 접근 차단은 `qa/automation/retired-feature.test.mjs` 및 Firestore 규칙 테스트에서 별도로 고정한다.

`qa:core-flow-smoke`는 일일 회귀 자동화가 자동 발견하는 smoke 이름 규칙에 맞춰 등록되어 있다. 일일 회귀는 Firebase 프로젝트나 QA 계정 상태에 영향을 주지 않도록 동일한 격리 E2E mock 서버에서 이 명령을 실행한다.

## 플랫폼 판정

브라우저 회귀는 작은 모바일 화면과 데스크톱 웹을 자동 판정한다. iOS·Android의 OS 권한, 키보드, 로컬 알림은 브라우저가 재현할 수 없으므로 릴리스 후보에서 다음을 실제 기기로 확인한다.

- iOS와 Android에서 로그인·가구 참여 후 각 탭 진입
- 소프트 키보드가 날짜·금액 입력과 저장 버튼을 가리지 않는지 확인
- VoiceOver·TalkBack으로 탭, 추가 버튼, 입력, 저장·삭제 버튼의 이름과 상태 확인
- 네트워크 단절·복귀 시 오프라인 안내가 노출되고 복귀 후 최신 가구 데이터를 다시 확인할 수 있는지 확인
- 알림 권한 허용·거부, 유통기한 로컬 알림 예약·취소 확인

동시 수정의 데이터 무결성은 `npm run test:firestore-rules`가 두 클라이언트의 동일 revision 경쟁을 만들어 먼저 저장된 값 보존과 stale writer 거부를 검증한다.
